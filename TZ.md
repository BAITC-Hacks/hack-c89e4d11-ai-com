# Техническое задание: терминальный FAQ-бот

## 1. Цель

Создать небольшое консольное приложение, которое отвечает только на пять
заранее заданных вопросов о репетиции HackAlem AI. Решение должно легко
запускаться проверяющим и демонстрировать безопасное поведение на неизвестных
запросах.

## 2. Основание и рамки

- трек: 03 «LLM-приложения»;
- задача: 01 «FAQ-бот на 5 вопросов»;
- формат: репетиция, не основной HackAlem AI;
- срок обязательной сдачи: 22 сентября 2026 года, 20:00;
- артефакт сдачи: репозиторий;
- ограничение: ровно 5 пар «вопрос–ответ» в `faq.txt`;
- достаточно совпадения по ключевым словам, RAG и LLM не требуются.

## 3. Пользовательский сценарий

1. Пользователь запускает `python bot.py`.
2. Бот показывает короткое приглашение.
3. Пользователь вводит вопрос на русском языке.
4. Бот нормализует ввод, сравнивает его с пятью FAQ-записями и печатает ответ.
5. Если уверенного совпадения нет, бот печатает ровно `не знаю`.
6. По команде `выход`, `exit`, `quit` или `q` программа завершается.

Дополнительно поддерживается режим одного запроса:
`python bot.py --once "текст вопроса"`.

## 4. Функциональные требования

### FR-1. База вопросов

`faq.txt` должен содержать ровно пять валидных записей. Каждая запись включает:

- непустой вопрос;
- непустой ответ;
- хотя бы одно ключевое слово.

Темы: время, команда, выбранный трек, состав сдачи, призы.

### FR-2. Поиск ответа

- регистр и знаки препинания не должны влиять на результат;
- `ё` и `е` должны считаться эквивалентными;
- выбор ответа учитывает пересечение ключевых слов и сходство строки;
- для принятого ответа требуется хотя бы одно совпавшее смысловое ключевое слово;
- выбирается одна запись с максимальной оценкой.

### FR-3. Безопасный отказ

Для пустого, постороннего или недостаточно похожего вопроса выводится `не знаю`.
Бот не должен генерировать или дополнять факты, которых нет в FAQ.

### FR-4. Ошибки данных

При отсутствии `faq.txt`, ошибке JSON или количестве записей, отличном от пяти,
приложение должно вывести понятную ошибку и завершиться с ненулевым кодом.

## 5. Нефункциональные требования

- Python 3.10+;
- только стандартная библиотека Python;
- кодировка файлов UTF-8;
- запуск на Windows, Linux и macOS;
- время ответа для пяти записей — практически мгновенное;
- логика поиска отделена от терминального интерфейса и покрыта тестами.

## 6. Алгоритм

1. Перевести запрос в нижний регистр, заменить `ё` на `е`.
2. Удалить знаки препинания и выделить слова.
3. Для каждой записи посчитать:
   - число совпавших ключевых слов;
   - коэффициент сходства с эталонным вопросом;
   - итоговую взвешенную оценку.
4. Выбрать запись с максимальной оценкой.
5. Вернуть её ответ только при прохождении порога и наличии ключевого совпадения;
   иначе вернуть `не знаю`.

## 7. Критерии приёмки

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| AC-1 | `python bot.py --once "Когда дедлайн?"` | Ответ содержит `22 сентября` |
| AC-2 | Вопрос `Сколько участников в команде?` | Ответ содержит `до 3 человек` |
| AC-3 | Вопрос `Какой у нас трек?` | Ответ содержит `LLM-приложения` |
| AC-4 | Вопрос `Что загружать для сдачи?` | Ответ содержит `репозиторий` |
| AC-5 | Вопрос `Будет денежный приз?` | Ответ сообщает, что призового фонда нет |
| AC-6 | Вопрос `Какая завтра погода?` | Ровно `не знаю` |
| AC-7 | `python -m unittest -v` | Все тесты проходят |
| AC-8 | В `faq.txt` не 5 записей | Понятная ошибка, код завершения 1 |
